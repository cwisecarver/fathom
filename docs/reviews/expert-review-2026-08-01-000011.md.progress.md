**Two places the review's recommended fix was wrong, both caught by measuring first:**

- **#14** — the review said to check the snapshot temp ("it is read for the MD5 anyway").
  Probed before building: `VACUUM INTO` *rebuilds indexes from table content*, so it REPAIRS
  index/table divergence. `quick_check` on the live file fails; on the VACUUMed copy it returns
  `"ok"` with all rows intact. Checking the temp would have shipped a gate that never fires.
- **#10** — the review said to delete the lock instead of rolling it back. Built it, and
  `S3StealTouchRollbackTest` caught it: with no lock object the next `acquire_lease` takes the
  `:not_found` branch — a fresh create at **epoch 1**, a *bigger* backward jump plus an
  unfenced takeover with no steal-touch, which is the hole round-2 #20 added the rollback to
  close. `epoch + 2` satisfies both findings.

**Discrimination, stated per finding:** #14's 3 tests and #10's updated rollback test fail on
the parent (`"the fencing epoch regressed to 3 after 4 was visible"`), as does 1 of #12's. #5's
three do NOT — the relaxation never escaped the snapshot's own connection, and the power-loss
window cannot be staged; they guard observable neighbours instead. Two of #10's new S3 tests
also do not — reaching the rollback needs a touch-failure seam the live backend lacks.

**Unmeasured cost:** #14 adds a full page scan per periodic flush. The flush has no gated bench
